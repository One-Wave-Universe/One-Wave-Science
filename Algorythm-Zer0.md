# Algorythm-Zer0

**Status:** Working canonical draft. Universal relational core is locked where explicitly defined; unresolved mechanics remain OPEN and must not be guessed.

Algorythm-Zer0 is the proposed universal recursive architecture for neural, control, hardware, matter, planetary, and simulation domains. Domain mappings may differ, but the relational grammar below is intended to remain invariant.

Physical and cosmological mappings remain hypotheses until independently derived or measured.

# 5. UNIVERSAL DEFINITIONS — LOCKED

## Reference / Ground

The local baseline against which relation, change, phase, direction, or deviation is measured.

Ground is not automatically an energy source, physical earth ground, voltage zero, temperature, or spatial origin. Each domain declares what its reference physically means.

## Field

The expressive relational context that defines the available Express/Compress choice for the current recursion.

Field has two locked jobs:

```text
1. DEFINE the current polarity choice.
2. CARRY the expressive relation that can become the next Field.
```

## Void

The compressive counterpart paired with the current Field. It constrains, concentrates, resolves, returns, or applies the relation.

## Polarity

The binary directional character of the decision:

```text
EXPRESS
or
COMPRESS
```

## Choice

Selection between Express and Compress as defined by the current Field.

Choice is a real selection operation. It is not universally reducible to one threshold equation.

## Phase

The relative position/timing of the Field and Void oscillation or recurrence.

Phase is not identical to polarity, amplitude, strength, state, scale, or choice.

## Move

```text
UP
STAY
DOWN
```

Working relational meaning:

```text
UP   = advance toward a higher/new relation
STAY = actively maintain the current relation
DOWN = return toward a lower/prior relation
```

These are relational moves, not necessarily literal spatial directions.

## View

A newly resolved relation made available upward for oversight or a higher recursion level.

## Action

The currently authorized relation applied downward to condition a lower recursion level.

## Inward / Outward / Across / Over

```text
INWARD  = toward center/reference/interior relation
OUTWARD = away from center/reference toward exterior relation
ACROSS  = peer-to-peer relation at the current level
OVER    = supervisory/bridging relation spanning a lower relation
```

Exact routing law remains OPEN.

## State

The currently retained local condition of the process.

## Scale

The extent, reach, or recursion size over which the current condition is treated as one relation.

## Mini / Small / Middle / Large / Macro

Ordered state/scale classes from least extent to greatest extent.

## Access

A currently available relation/path for propagation, processing, action, or recursion.

## Open

Make an access relation usable.

## Close

Stop using an access relation without requiring destruction of retained state.

## Hold

Actively preserve the current relation around its reference without advancing or releasing it.

## Redirect

Change which path/orientation is used while preserving continuity of the larger process.

## Break / Release

End or loosen the current commitment sufficiently for the relation to reorganize.

## Loop

Feed the resulting process condition back into recursion.

## Oversight

Compare the new view upward against the reference and the current/last authorized action downward.

## Override

Intervene in, reroute, hold, reverse, or release an existing downward action when oversight requires it.

## Memory

```text
PROCESS = MEMORY
```

Memory is retained process state, not a separate conceptual storage box.

```text
state is held in active process
→ relation arrives
→ same local state changes
→ changed state remains available
→ next relation acts on changed state
```

# 20. STILL NEEDED — DO NOT GUESS

The unresolved mechanics are:

## A. Field-definition payload

What information must a Field contain so it can define the current Express/Compress choice in any domain?

## B. Choice policy

What constrains valid Choice? Can it be learned, stochastic, deterministic, deliberative, or physically forced depending on implementation? How exactly does Express or Compress instantiate the new Field?

## C. Phase law

What exactly is Field phase? What is Void phase? How is relative phase calculated? How does phase constrain available choice without replacing Choice?

## D. UP / STAY / DOWN law

What determines or permits each move? Is Move always chosen, sometimes constrained, or sometimes physically forced?

## E. Orientation law

What selects Inward / Outward / Across / Over? Can more than one orientation be active simultaneously?

## F. State / Scale law

What promotes/demotes Mini / Small / Middle / Large / Macro? Are State and Scale always one axis or can they separate?

## G. Recursive-step law

Exact conditions for Begin → Build 1 → Hold → Build 2 → Break/Release → Loop.

## H. Oversight / Override law

Exact coherence/mismatch conditions for Allow / Hold / Redirect / Override / Break-Release.

## I. Point / Path / Rotation / Field / Volume promotion law

Exact criteria for Point → Path → Rotation → Field → Volume → next-scale Point.

## J. Timing law

Field/Void update order, phase lead/lag, minimum dwell, sampling/update rate, overlap/alternation, and when Choice occurs relative to phase.

## K. Hysteresis law

Exact use of transition gaps and separate entry/exit rules.

## L. Reference adaptation law

Is reference fixed, locally adaptive, or recursively inherited? When may it move? How is drift distinguished from legitimate adaptation?

## M. Rate limits

May a relation jump multiple bands/states or must it traverse neighboring states?

## N. Danger response

Exact behavior in 90–100 expression danger and 0–10 compression danger: warning, constrained choice, resolving, override, break/release, or terminal failure.

## O. Conflict law

What happens if Field and Void constraints conflict while multiple choices remain available?

## P. Scale-coupling law

When does a lower resolved volume become one higher-scale point? How can higher oversight act downward without destroying lower local state?

## Q. Structural-depth transition law

What moves Scalar → Differential → Vector → Tensor → Stratum → Harmonic?

## R. Lifecycle transition law

Exact conditions for Idle → Primed → Executing → Vectoring → Resolving → Idle.

## S. Normalization law

How do domain-specific measurements map into shared relational coordinates without pretending unlike quantities share physical units?

## T. Output contract

What does one resolved loop output: new Field, new relation, access path, action, motor command, physical state change, or higher-scale point?

## U. Conservation / resource accounting

Physical versions must account for energy/work/material transfer. Software/neural versions need bounded resource accounting where relevant. Recursion must not silently create gain, information, energy, or authority.

## V. Failure / falsification contract

Every implementation must declare what result would show that its mapping or transition rule is wrong.
