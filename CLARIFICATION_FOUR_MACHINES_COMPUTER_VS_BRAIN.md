# Four Machines — Computer vs Brain

This file exists because the same words were being used for four different builds.
It does not replace G-741, VTC_BUILD_ARCHITECTURE, One_Wave_Bench/brain, AGENTS.md, G-740, or G-742.
It tells you which one you are holding.

## 1. The four machines

| ID | File | Job | Body |
|---|---|---|---|
| M1 | `AGENTS.md` | Field/Void software-construction engine (code, apps, programs) | none |
| M2 | `One_Wave_Bench/brain/` | command + receipt + constellation memory runtime | none yet (no mic, no motors) |
| M3 | `VTC_BUILD_ARCHITECTURE.md` | triad / three Mirror-Gate hardware ladder (F0→F3) | bench parts |
| M4hw | `Nodes/G-741_Crazy_Town_Balanced_Rail_Nested_Loop_Build_Proposition.md` | millivolt 2-rail + virtual ground + bidirectional MOSFET nested loops | unbuilt electronics |

M4 in `AGENTS.md` is the **orchestrator** (OpenClaw). M4hw above is the **hardware proposition**. Do not collapse those two names.

## 2. Computer vs brain

| Word | Means here |
|---|---|
| Computer | kernel + receipts. Can live in software (M2) or on rails (M4hw / M3). No claim it is a mind. |
| Brain | that kernel plus a nonverbal loop (G-742) plus something that can be wrong in the world |
| Jar | leftover talk with no distributed net to match. Not a build target. |
| R2 / android | minimum legal body: cheap match, leftover free for maps and talk |

One Wave **computer** is possible without an android.
One Wave **brain** is not a jar. It needs a simple world loop.

## 3. Parent order for the next hardware month

```text
P0 spine (G-741)
  -> F0 triad hangs on that spine (VTC-F0)
    -> M2 software is the test harness / receipt logger
      -> R2-scale body is the first match for oversight
```

P0 is two rails and a local virtual ground. No oscillator required.
F0 is the first A / -A + evaluator that **uses** that mid. It does not invent a second mid.
Do not start F1, quadratic views, motors, or a seventh route before P0 receipts exist.

## 4. Vocab adapter (same three slots)

| Slot | Updated 43 | VTC | Bench Field | Bench Void | G-741 |
|---|---|---|---|---|---|
| + / one way | YES / UP | EVERYTHING + RIGHT | EXPRESS | CONFIRM | + rail kick |
| 0 / mid | HOLD | NOTHING / STAY | HOLD | DEFER | virtual ground / dead band |
| - / other way | NO / DOWN | NOTHING or LEFT as signed move | COMPRESS | DENY | - rail kick |

Rules:

- Mid is ternary 0 from topology, not a harvested third rail.
- DEFER is Hold. DENY is Override. Do not collapse them.
- Field and Void keep both vocabularies. Neither side eats the other.
- Older `-2,-1,0,+1,+2` language is compatibility shorthand only (Updated 44).

## 5. Nested loops without extra math

Child loop does not invent physics.
Child `V0` hangs on the parent pair.
Three sizes is enough to start: node, small loop, middle pair.
That is the same idea as VTC: triad → cluster → cube. Different packaging, same hang-the-zero rule.

## 6. What is already ahead vs behind

Ahead:

- six-route software logic and lifecycle language
- constellation / Hopfield / receipt memory in `One_Wave_Bench/brain/`
- routing contract in G-740
- nonverbal requirements in G-742 (written, not executed)

Behind:

- G-741 P0 measurement
- VTC-F0 measurement
- any body adapter (G-742 drum / sensor / motor experiments)
- a single packet that P0/F0 can hand to constellation memory

Do not invent another memory architecture until P0/F0 emit a receipt M2 can store.

## 7. Next measured step

One branch-step only:

**Characterize P0.** Two rails, local `V0`, no oscillator, no motor.
Write rail voltages, mid drift, noise, and proof that `V0` is not earth and not a current sink.
Hard stop when that receipt exists.

Then F0 may hang on it.
