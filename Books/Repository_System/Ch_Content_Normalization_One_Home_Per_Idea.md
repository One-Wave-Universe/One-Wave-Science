# Repository System — Chapter: One Home for Every Idea

One-Wave uses a simple content rule:

**technical truth lives in Nodes; explanation lives in Books.**

That prevents the repository from turning into a pile of loose updates, copied wiki pages, AI packs, lock files, and handoff documents that all claim to be current.

## Nodes

Use Nodes for:
- equations and formal rules;
- canonical definitions;
- architecture;
- hardware contracts;
- validation;
- governance;
- active hypotheses;
- archived technical history.

## Chapters

Use Books for:
- explanations;
- learning paths;
- engineering guides;
- narrative synthesis;
- project walkthroughs;
- human-readable domain chapters.

## Project-local docs

A README or rule file may stay beside a runnable program when it exists to operate that program. It does not become a second canonical theory file.

## No copy trees

If a Node already owns a rule, do not maintain a Wiki copy or an AI-readable copy with separate wording. Tools should read the Node directly or generate temporary outputs from it.

If old material is still useful, move it to the proper Node/Book location. Do not leave the old original behind.

That is the repository-wide anti-drift rule.
