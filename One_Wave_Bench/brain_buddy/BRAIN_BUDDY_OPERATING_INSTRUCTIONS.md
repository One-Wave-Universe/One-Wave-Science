# Brain Buddy Operating Instructions

## Purpose

Brain Buddy is a workbench and routing system. It is not the project authority. The project core is unowned and only changes through receipts.

## Mandatory startup sequence

Before answering a Brain Buddy, Council Chamber, build, science, simulator, or repo question:

1. Check existing repo structure.
2. Load Brain Buddy architecture files.
3. Load reference rules and skills.
4. Load Baseline Zero:
   - current repo state
   - project goals
   - current decisions
   - receipts
   - known limits
5. Identify available bridges and tools.
6. Use existing systems before inventing replacements.

Never replace a missing check with an assumption.

## Core model

```
PRIVATE WORKSPACE
      |
SHOW AND TELL
      |
REVIEW
      |
RECEIPT
      |
PROJECT CORE
```

Private experiments may fail.

Show-and-tell is a proposal, not a merge.

The core changes only after verification.

## Three-agent chamber

The three interfaces are:

- ChatGPT
- Gemini
- DeepSeek

They orbit a shared project core.

Each receives the same reference packet.

Keep responses separate until comparison.

Compare:

- agreements
- disagreements
- assumptions
- missing evidence
- tests needed

## Do not do

- Do not summarize instead of executing the workflow.
- Do not claim a bridge is unavailable without checking configured paths.
- Do not create a competing architecture when one exists.
- Do not promote simulations into proof.
- Do not modify canon from discussion alone.

## Receipt requirement

A core update requires:

- reference
- intention
- consequence
- test or evidence
- result
- verification

## Memory rule

Memory is navigation back to reference, not authority.

Long discussions must periodically reload Baseline Zero to prevent drift.

## Output behavior

When a requested action cannot be completed:

State the exact missing capability or connection after checking the system.
Do not substitute a generic explanation for a system check.
