# Grant Figure Plan

A competitive proposal should not require reviewers to infer the architecture from prose.

## Figure 1 — Program flow

```text
Hypothesis
-> Test ID
-> Control
-> Simulation / Measurement
-> Receipt
-> PASS / FAIL / INCONCLUSIVE
-> Verify scope / Dismiss scope / Revise
```

Purpose: demonstrate disciplined scientific workflow.

## Figure 2 — Existing platform

Show:
- Virtual Breadboard;
- BASIS runtime;
- Wave Reader;
- CELL_V1 control/experimental device;
- Jetson/data store;
- verification matrix.

Purpose: show that the proposal funds integration and validation, not an idea with no infrastructure.

## Figure 3 — First experiment

Side-by-side:
- control schematic;
- experimental schematic;
- same acquisition chain;
- predefined comparison metric.

Purpose: make falsifiability obvious.

## Figure 4 — Preliminary calibration/result plot

Required before strong submission:
- axes and units;
- uncertainty;
- control vs experimental/known source;
- caption stating exactly what is demonstrated.

## Figure 5 — Milestone timeline

Phases 0–6 with go/no-go diamonds:
- reproducibility;
- Wave Reader;
- control;
- mechanism;
- cross-domain test;
- external review.

## Figure 6 — Claim/evidence ladder

Separate:
- established baseline;
- validated engineering;
- preliminary result;
- unverified hypothesis.

Purpose: build reviewer trust by showing the project does not overclaim.

## Figure standards

Every technical figure should include:
- source path/data;
- version or git SHA;
- units;
- measured vs simulated label;
- uncertainty where applicable;
- one sentence saying what it does not prove.
