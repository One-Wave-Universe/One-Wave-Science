# Virtual Breadboard Simulator — Android

The Android app is the **same simulator** as the browser and desktop builds:
the same `index.html`, `style.css` and `js/` (including `js/circuit.js`, the
MNA solver) run inside an Android WebView. Nothing is rewritten for mobile, so
a circuit JSON, receipt or regression result means the same thing on every
platform.

There are two Android tracks. Use **Track A (Capacitor)** unless you
specifically need the no-Gradle build.

| | Track A — Capacitor (`mobile/`) | Track B — legacy hand-built APK (`android/`) |
|---|---|---|
| Status | Recommended, maintained | Kept for reference / offline apt-only builds |
| Toolchain | Node 22+, JDK 21, Android SDK (Gradle wrapper included) | `aapt`, `smali`, `zipalign`, `apksigner` from apt |
| Target SDK | 36 (min SDK 24, Android 7.0+) | 23 (min SDK 19) — Play Store won't accept it, and newer Android versions may refuse or warn on install |
| Outputs | debug APK, release APK, Play Store AAB | one self-signed APK |
| CI | [`breadboard-android-build.yml`](../.github/workflows/breadboard-android-build.yml) | none |
| Web assets | copied fresh from `../index.html`, `../style.css`, `../js/` on every sync | copied on every `build-apk.sh` run; the committed `.apk` can be older than `js/` |

## Track A — Capacitor (recommended)

```text
Virtual_Breadboard/
  index.html, style.css, js/      <- the one engine + UI (unchanged)
  mobile/
    package.json                  <- Capacitor deps + android:* scripts
    capacitor.config.json         <- appId, appName, webDir = www
    scripts/copy-www.js           <- stages ../index.html ../style.css ../js -> www/
    scripts/ensure-android.js     <- runs `cap add android` on first use
    scripts/gradle.js             <- calls gradlew / gradlew.bat
    www/        (generated, gitignored)
    android/    (generated by `cap add android`, gitignored until customized)
```

### Prerequisites

- **Node.js 22+** (Capacitor 8 requirement; the desktop Electron build still works on Node 20)
- **JDK 21** (`JAVA_HOME` set)
- **Android SDK** with platform 36 + build-tools — easiest via Android Studio,
  or the command-line tools:
  `sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"`,
  then set `ANDROID_HOME` (or write `sdk.dir=...` into `mobile/android/local.properties`).

### Build a sideloadable APK

From `Virtual_Breadboard/`:

```bash
cd mobile
npm install
npm run android:apk
# -> mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

Or from `Virtual_Breadboard/` without `cd`: `npm run android:apk` (forwards to `mobile/`).

Copy `app-debug.apk` to the phone and open it (allow "install unknown apps"
for the file manager/browser you opened it with), or with USB debugging on:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

### All scripts (`mobile/package.json`)

| Script | What it does |
|---|---|
| `npm run www` | Stage `../index.html`, `../style.css`, `../icon.svg`, `../js/**` into `www/` and verify every local `<script src>`/`<link href>` in `index.html` exists |
| `npm run android:add` | `cap add android` if `android/` doesn't exist yet |
| `npm run android:sync` | `www` + `android:add` + `cap sync android` — run after any web change |
| `npm run android:open` | Sync, then open the project in Android Studio |
| `npm run android:run` | Sync, then install + launch on a connected device/emulator |
| `npm run android:apk` | Sync, then `gradlew assembleDebug` (debug-signed APK) |
| `npm run android:apk-release` | Sync, then `gradlew assembleRelease` (needs signing config, see below) |
| `npm run android:aab` | Sync, then `gradlew bundleRelease` (Play Store bundle; needs signing) |

Because `copy-www.js` copies the whole `js/` folder, new engine/UI files
(e.g. a perfboard layout in `js/board.js`, or new `js/*.js` modules referenced
from `index.html`) reach Android on the next sync with no mobile changes.

### CI (no secrets)

[`.github/workflows/breadboard-android-build.yml`](../.github/workflows/breadboard-android-build.yml)
runs `npm install && npm run android:apk` on Ubuntu and uploads
**`android-debug-apk`** (`VirtualBreadboardSimulator-debug.apk`) as a workflow
artifact. It runs on pull requests / pushes to `main` that touch
`Virtual_Breadboard/mobile/**`, on tags `build-android-*`, and manually from
the Actions tab (**Run workflow**, once the file is on `main`). Debug APKs are
signed with the runner's throwaway debug key: fine for sideloading and
testing, not for the Play Store, and a newer CI build may need an uninstall
first if its debug key differs.

### Release signing / Play Store (not set up)

1. Generate an upload keystore **outside the repo** (`keytool -genkeypair ...`).
2. Add a `signingConfigs.release` block to `mobile/android/app/build.gradle`
   reading the keystore path/passwords from environment variables or
   `~/.gradle/gradle.properties` — never commit the keystore or passwords.
3. `npm run android:aab` → upload `app-release.aab` to Play Console.
4. For CI release builds, store the keystore (base64) + passwords as repo
   secrets and decode them in a separate, tag-triggered job.

When you customize the native project (icons, splash, permissions, signing),
remove `android/` from `mobile/.gitignore` and commit `mobile/android/` so the
changes are kept; `ensure-android.js` will then skip `cap add`.

### App identity

`appId` is `com.onewavescience.virtualbreadboard` — the same package name as
the legacy APK, so the Capacitor build is its successor. Android won't install
one over the other (different signing keys): uninstall the legacy app first.

### Known WebView differences

- **File downloads** (**Export** circuit HTML, scope **Export CSV**) use `<a download>` with
  blob URLs, which an Android WebView doesn't save by default. Use
  **Read board JSON** / **Measure / receipt** and copy the text instead, or add
  a Capacitor Filesystem/Share plugin later.
- **Save / Load** uses `localStorage`; it persists per-app on the device.
- **AI dialogue box** calls third-party APIs with `fetch()`; it works only if
  the device is online and the provider allows the request (same as browser).
- **Touch**: `js/app.js` already has touch handlers (tap-to-place via the
  browser's tap→click, finger drag on potentiometer knobs, press-and-hold
  pushbuttons). They're registered as passive, so the page can also scroll
  during a knob drag — use the Inspector slider if that's awkward on a small
  screen. The full 63-column board is wide; landscape works best on phones.

## Track B — legacy hand-built APK (`android/`)

`android/VirtualBreadboardSimulator.apk` is a ~50 KB WebView wrapper built
without Gradle or Google SDK downloads (smali → dex, `aapt`, `zipalign`,
`apksigner` from Ubuntu/Debian apt). It targets SDK 23, and the committed APK
may lag behind `js/` — rebuild before trusting it:

```bash
sudo apt-get install --no-install-recommends \
  aapt zipalign apksigner android-sdk-platform-23 libsmali-java
cd android && ./build-apk.sh   # -> android/build/VirtualBreadboardSimulator.apk
```

Its keystore password is in `build-apk.sh`, so treat it as a sideload-only
test signature, not a release identity.
